# E1-3 보너스 과제

2026-11-10에 공식 원문의 보너스 두 항목을 구현했다. 외부 라이브러리 없이 반복문과 표준 라이브러리만 사용한다.

## 패턴 생성기

```bash
python3 main.py
# 메뉴 3 → N 입력 → 1(Cross) 또는 2(X) 선택
```

N은 1~101 정수다. Cross는 0부터 센 `N // 2`행과 열이 1이고, X는 두 대각선이 1이다. 짝수 N의 Cross도 한 행·한 열을 사용하며 가운데 두 행 중 아래쪽, 두 열 중 오른쪽을 선택한다. N=1·2에서는 두 패턴이 겹쳐 판정 불가가 될 수 있으며 이를 숨기지 않는다. 크기 상한은 콘솔 출력과 대기 시간을 제한하기 위한 정책이다.

생성한 Cross/X를 모두 출력한 뒤 선택한 패턴을 **기존 모드 1의 `run_manual(pattern=..., filters=...)`에 직접 전달**한다. A는 Cross, B는 X 필터로 채운다. 판정·기존 평균 시간 출력·2D/1D 성능 비교에서 같은 생성 데이터를 재사용한다. 기존 메뉴 1의 직접 입력 3×3 흐름과 메뉴 2의 공식 data.json은 그대로 사용할 수 있다. 생성기로 공식 데이터 파일을 덮어쓰지 않는다.

## 1차원 배열 MAC과 비교

메뉴 4는 N=3·5·13·25의 생성 패턴으로 2D/1D를 비교한다. 메뉴 3은 사용자가 고른 N으로 비교한다.

- `flatten()`은 행 우선 순서로 N² 길이 리스트를 만든다.
- `mac_flat()`은 인덱스 반복문으로 직접 곱하고 더한다. 2D의 mac과 누적 순서가 같으며 점수 일치를 검사한다.
- 동일 입력·필터를 사용하고 각 구현을 **1000회 × 5라운드** 실행한다. 라운드마다 실행 순서를 번갈아 바꾸고, 워밍업 후 호출당 평균 시간의 중앙값을 비교한다.
- 변환은 반복 측정 전에 한 번만 하고 그 시간도 별도로 출력한다. 단발 실행의 비용은 변환까지 포함해 판단해야 한다.

**[실측 성능 표](records/bonus-performance.md)** · [검증 JSON과 원시 측정값](records/bonus-verification.json) · [CLI 입력·출력](records/bonus-cli.txt)

텍스트 로그는 줄끝 공백만 정리했으며, 보너스 JSON의 stdout에는 수집한 출력을 그대로 보관했다.

두 방식 모두 시간 복잡도는 O(N²)이다. 1D 변환에는 O(N²) 추가 공간이 필요하다. Python 리스트는 객체 참조를 보관하므로 실제 연속 숫자 메모리나 NPU의 온칩 메모리를 구현한 것은 아니다. 인덱스 접근을 단순화했을 때 이 환경에서 어떤 차이가 관측되는지 확인하는 실습이며, 속도 향상을 보장하지 않는다.

## 검증

```bash
python3 scripts/verify_submission.py
python3 scripts/verify_bonus.py
```

기본 동작 16개 검사와 보너스 58개 검사를 실제 WSL Python에서 통과했다. 기본 3×3 예시, 공식 JSON의 기존 총 6/통과 3/실패 3을 유지한다. 보너스 검사는 크기·이진값·십자가 축·X 대각선, 짝수/최소/최대 크기, 범위 오류, 일반 실수 데이터의 MAC 동등성, 잘못된 모양·길이·유한값·반복 수, 생성기 EOF 및 CLI 재사용을 확인한다.

성능 값은 실행 환경에 따라 달라지며 최신 실행값은 위 검증 파일에 남긴다. 기존 2026-11-09 캡처는 기본과제 당시의 기록이다. [main.py 354줄 전체 설명자료](code/main_line_by_line.html)는 보너스 코드까지 포함해 2026-11-10에 갱신했다. `[보너스]`로 검색하면 추가·변경 설명을 찾을 수 있다. 재생성 명령은 `python3 scripts/build_code_guide.py`이며 소스 지문이 바뀌면 설명 재검토를 요구한다.
